      文本：标题、段落与强调

      网页上大部分内容都是文字。下面这些标签覆盖了 90% 的场景。

      文本标签
      要点

      标题标签按层级选，不按大小选。想要小字体的一级标题，用 CSS 改字号，不要因为字小就用 h4。搜索引擎和读屏软件靠 h1~h6 理解文章结构。

      易混

      <strong> 表示"重要"，<b> 只是加粗；<em> 表示"强调语气"，<i> 只是斜体。HTML5 推荐用有含义的 strong 和 em。

      块级元素与行内元素

      这是学 CSS 布局前必须分清的概念。蓝色是块级元素，橙色是行内元素。

      两种元素的排列方式
      类型表现常见元素
      块级 block独占一行，宽度默认 100%，能设宽高div p h1~h6 ul ol li table form header main section footer
      行内 inline和别的元素排在一行，宽高由内容决定，设置宽高无效span a strong em code label
      行内块 inline-block排在一行，但能设宽高img input button select textarea
      嵌套规则

      块级元素可以包含行内元素，行内元素不要包含块级元素。特别注意：<p> 里不能放 <div> 或另一个 <p>，浏览器会自动把 p 提前关闭，导致结构错乱。HTML5 中 <a> 是例外，它可以包住一整块内容（比如一张商品卡片）。

            层叠、继承与优先级

            CSS 的全称是“层叠样式表”。同一个元素被好几条规则同时命中、而且改的是同一个属性时，浏览器按下面的顺序决定听谁的。

            1. !important 最优先（尽量别用）。
            2. 其次比优先级：行内 style > ID > 类 / 属性 / 伪类 > 元素 / 伪元素。
            3. 优先级一样，后写的覆盖先写的。
            这段字最后是什么颜色？

            优先级计算器

            优先级是三个数字 (ID 数, 类数, 元素数)，从左往右逐位比较，左边的一位大就直接赢，不会“进位”。输入两个选择器比一比。

            继承：有些属性会传给子元素

            给 body 设置 color 和 font-family，整页文字都会跟着变，因为文字类属性（color、font-*、line-height、text-align 等）会被子元素继承。盒子类属性（width、padding、margin、border、background 等）不会继承，否则每一层都会多出一圈边框。

            避坑

            样式不生效时，打开浏览器开发者工具（F12）的 Elements 面板，选中元素看右侧 Styles：被划掉的那条就是“输了”的规则，上面那条是赢家。

                  01
                  从输入网址到看到页面
                  
      
                  这是前端面试第一高频题，也是理解整个 Web 的主线。用下面的按钮一步步走一遍。
                  
      
                  
        
                  
        
                  
        
                  
      
                  
      
                  一句话版
                  DNS 把域名换成 IP → 建立 TCP 连接（HTTPS 再加一层 TLS 加密）→ 发 HTTP 请求 → 服务器返回 HTML → 浏览器解析 HTML 和 CSS、执行 JS → 计算布局 → 画到屏幕上。
                  
    
                  

    
    
                  
      
                  02
                  HTTP 请求和响应长什么样
                  
      
                  HTTP 本质上就是按固定格式写的两段文字：浏览器发一段请求，服务器回一段响应。点开每一行看含义。
                  
      
                  
        
                  请求 Request浏览器 → 服务器
                  
        
                    
      
                    
      
                    
        
                    响应 Response服务器 → 浏览器
                    
        
                      
      
                      
      
                      结构
                      两者结构一样：第一行（请求行 / 状态行）+ 若干头部（键: 值）+ 一个空行 + 正文（可以没有）。GET 请求一般没有正文，参数放在网址的 ? 后面。
                      
    
                      

    
    
                      
      
                      03
                      请求方法与状态码
                      
      
                      方法说明“想干什么”，状态码说明“结果如何”。设计和调用 REST 接口时，这两样就是双方的约定。
                      
      
                      
        
                      方法含义例子
                      
        
          
                      GET读取数据，不应该修改任何东西GET /api/todos
                      
          
                      POST新建一条数据，或提交一个动作（登录）POST /api/todos
                      
          
                      PUT整条替换PUT /api/todos/3
                      
          
                      PATCH只改其中几个字段PATCH /api/todos/3
                      
          
                      DELETE删除DELETE /api/todos/3
                      
                              
      
                      
      
                      状态码：点一个看含义
                      
      
                      第一位数字就是分类：2 成功，3 重定向，4 客户端（请求方）的错，5 服务器的错。

                      05
                      常用请求头与缓存
                      
      
                      头部是请求和响应的“附加说明”。下面这些是写全栈项目时一定会碰到的。
                      
      
                      
        
                      头部方向作用
                      
        
          
                      Content-Type双向正文是什么格式：application/json、text/html、multipart/form-data（上传文件）
                      
          
                      Accept请求希望服务器返回什么格式
                      
          
                      Authorization请求身份凭证，常见 Bearer <token>
                      
          
                      Cookie / Set-Cookie请求 / 响应服务器用 Set-Cookie 让浏览器存一小段数据，之后浏览器每次请求同一站点都自动带上 Cookie。登录状态常靠它
                      
          
                      Cache-Control响应能缓存多久：max-age=31536000 缓存一年，no-store 不缓存
                      
          
                      ETag / If-None-Match响应 / 请求内容指纹。浏览器带上旧指纹来问，没变就返回 304，省去重新下载
                      
          
                      Location响应重定向去哪，或新建资源的地址
                      
          
                      Access-Control-Allow-Origin响应允许哪些网站跨域读取，见第 07 节
                      
                              
      
                      
      
                      缓存套路
                      Vite 打包出来的文件名带哈希（index-3f9a2c.js），内容一变名字就变，所以可以放心设置“缓存一年”。而 index.html 不缓存或短缓存，保证用户每次都能拿到最新的文件名。

                      07
                      同源策略与跨域 CORS
                      
      
                      浏览器规定：一个网页里的 JS 默认只能读取同源接口的响应。协议、域名、端口三者完全一样才叫同源。输入两个网址比一比。
                      
      
                      
        
                      
          
          
          
                      
          
                      
          
                      换一组：
                      
        
                      
      
                      
      
                      跨域时浏览器怎么做
                      
      
                        
        
                      1. 前端 localhost:5173 用 fetch 请求后端 localhost:3000，端口不同，跨域了。
                        2. 
        
                      2. 如果是“非简单请求”（比如带 JSON 正文的 POST、带 Authorization 头），浏览器先自动发一个 OPTIONS 预检请求，问后端“允许吗？”
                        3. 
        
                      3. 后端在响应头里写 Access-Control-Allow-Origin: http://localhost:5173（以及允许的方法和头），浏览器才放行。
                        4. 
        
                      4. 没有这个头，请求其实已经到了服务器，但浏览器拦下响应不给 JS 看，控制台出现红色的 CORS 报错。
                        5. 
      
                      
      
                      怎么解决
                      CORS 是后端要配的：Express 里装 cors 中间件即可。开发时也可以在 Vite 里配置代理，让前端请求同源的 /api，由开发服务器转发到后端。用 Next.js 把前后端放在同一个项目里，就根本不跨域。
                      
    
                      

    
    
                      
      
                      08
                      安全基础：XSS、CSRF 与 HTTPS
                      
      
                      运行下面的代码，然后分别点两个按钮。输入框里那段“评论”其实是一段攻击代码。
                      
      
                      
        
                      XSS 演示
                      
        

      
                      
      
                      
        
                      攻击怎么发生怎么防
                      
        
          
                      XSS 跨站脚本把别人提交的内容当 HTML 插进页面，里面藏的脚本被执行，可以偷走登录凭证用 textContent；React 默认会转义；后端也要过滤；登录 Cookie 设 HttpOnly 让 JS 读不到
                      
          
                      CSRF 跨站请求伪造你登录了 A 网站，又打开了恶意网站 B，B 偷偷向 A 发请求，浏览器自动带上 A 的 CookieCookie 设 SameSite=Lax；重要操作加 CSRF Token；改数据只用 POST / PUT / DELETE
                      
          
                      中间人窃听HTTP 是明文，公共 Wi-Fi 上能被看到和篡改全站 HTTPS。Vercel、Netlify 等平台默认自动配好
                      
          
                      SQL 注入把用户输入直接拼进 SQL 语句用参数化查询或 ORM（后端模块会讲）
                      
                              
      
                      
      
                      核心原则
                      永远不要信任来自用户的数据。前端校验只为体验，后端必须再校验一次。

                        01
                        为什么要用框架
                        
      
                        同样做一个计数器，看看两种写法的差别。
                        
      
                        
        
                        原生 JS：命令式，一步步告诉浏览器怎么改
                        let count = 0;
const btn = document.querySelector("#btn");
const text = document.querySelector("#text");

btn.addEventListener("click", () => {
  count++;
  text.textContent = count;        // 手动同步界面
  if (count > 5) text.style.color = "red"; // 每个地方都要记得改
});
                        数据和界面要手动保持一致，功能一多就容易漏改。
                        
        
                        React：声明式，描述界面应该长什么样
                        function Counter() {
  const [count, setCount] = useState(0);

  return (
    <button onClick={() => setCount(count + 1)}>
      <span style={{ color: count > 5 ? "red" : "inherit" }}>
        {count}
      </span>
    </button>
  );
}
                        只改数据（state），React 自动算出界面要变哪里。
                        
      
                        
      
                        state 变了→组件函数重新执行→得到新的界面描述→React 对比新旧差异→只更新变化的 DOM
                        
      
                        核心公式
                        UI = f(state)。界面是数据的函数。记住这一句，React 的大部分设计都能想通。
                        
      
                        
        
                        框架特点全栈搭档
                        
        
          
                        React生态最大，招聘需求最多，本计划的默认选择Next.js
                        
          
                        Vue上手平缓，模板语法接近 HTML，国内很流行Nuxt
                        
          
                        Svelte编译时框架，代码量少，运行快SvelteKit
                        
          
                        Angular大而全，适合大型企业项目自带
                        
                                
      
                        
    
                        

    
    
                        
      
                        02
                        JSX：在 JS 里写界面
                        
      
                        JSX 看起来像 HTML，其实是 JS。花括号 { } 里可以放任何 JS 表达式。改一改 user 再点运行。

                        class 要写成 className<div className="card">

                        所有标签都要闭合<img />、<input />、<br />

                        03
                        组件与 props
                        
      
                        组件就是一个返回 JSX 的函数。props 是父组件传进来的参数，像 HTML 属性一样写。同一个组件传不同的 props，就能复用。

                        注意
                        props 是只读的，组件不能修改自己收到的 props。数字、布尔值、对象要用花括号传：days={1}；只写属性名等于 true。
                        
    
                        

    
    
                        
      
                        04
                        state 与事件
                        
      
                        useState 给组件一块“会触发重新渲染的记忆”。调用 setXxx 更新它，React 就会重新执行组件函数，界面随之更新。
                        
      
                        
        
                        Counter.jsx打开控制台看渲染次数
                        

      
                        
      
                        三个新手必踩的坑
                        
      
                        
        
                        错误写法为什么不行正确写法
                        
        
          
                        count = count + 1直接改变量，React 不知道，界面不更新setCount(count + 1)
                        
          
                        onClick={setCount(1)}渲染时就立刻执行了，还会无限循环onClick={() => setCount(1)}
                        
          
                        list.push(x); setList(list)同一个数组，React 认为没变setList([...list, x])
                        
                                
      
                        
      
                        基于旧值更新
                        连续多次更新时用函数写法：setCount(c => c + 1)。它拿到的总是最新值。
                        
    
                        

    
    
                        
      
                        05
                        列表渲染与条件渲染
                        
      
                        用数组的 map 把数据变成一组元素，每个元素要有一个稳定且唯一的 key。条件渲染就是普通的 JS：三元运算符和 &&。

                        useState组件自己的数据
                        
          
                        useEffect副作用：请求、订阅、定时器、同步到外部
                        
          
                        useRef拿 DOM 元素；存一个改了也不需要重新渲染的值
                        
          
                        useContext读取上层提供的共享数据

                            05
                            Git 基础
                            
      
                            Git 记录项目的每一次修改，可以随时回退，也能多人并行开发。先理解三个区域，再到第 11 节的终端里亲手敲一遍。

                            命令作用
                            
        
          
                            git init把当前目录变成 Git 仓库（只做一次）

                            git add 文件 / git add .把改动放进暂存区 / 放进全部改动

                            git log --oneline看提交历史
                            
          
                            git diff看具体改了哪些行

                                    01
                                    后端做什么
                                    
      
                                    前端负责展示和交互，后端负责前端不能做、也不该做的事：保存数据、校验权限、处理业务、对接其他服务。
                                    
      
                                    浏览器（React）— HTTP 请求 →API 服务器（Node.js）— SQL →数据库
                                    
      
                                    
        
                                    为什么不能都在前端做原因
                                    
        
          
                                    数据要多人共享localStorage 只在自己的浏览器里，别人看不到
                                    
          
                                    前端代码谁都能看、都能改权限判断、价格计算放前端，用户改一下就绕过了
                                    
          
                                    密钥不能暴露数据库密码、支付密钥只能放在服务器上
                                    
                                            
      
                                    
      
                                    为什么选 Node.js
                                    后端语言很多（Java、Go、Python、PHP），Node.js 的好处是和前端同一门语言，学完 JavaScript 就能直接写。npm 生态也是共用的。
                                    
    
                                    

    
    
                                    
      
                                    02
                                    Node.js：在浏览器之外运行 JS
                                    
      
                                    Node.js 让 JS 能在电脑和服务器上运行。语言完全一样，只是环境不同：没有 document 和 window，但可以读写文件、监听端口、连数据库。
                                    
      
                                    
        
                                    server.js不用任何框架的最简服务器
                                    
        
                                      
      
                                      
      
                                      node server.js          # 运行
node --watch server.js  # 改代码后自动重启（Node 18.11 以上）
                                      
      
                                      
        
                                      浏览器里的 JSNode.js
                                      
        
          
                                      全局对象window、documentprocess、global
                                      
          
                                      能做操作页面、请求接口读写文件、开服务器、连数据库

                                      03
                                      Express：几行代码写出接口
                                      
      
                                      原生写法要自己解析网址和正文，很繁琐。Express 是最经典的 Node.js 框架，用 app.get(路径, 处理函数) 定义接口。下面是一个在页面里模拟运行的 Express：改代码，点“运行”启动服务器，再用右边的请求面板发请求。
                                      
      
                                      
        
                                      server.js改完点“运行”重启服务器
                                      
        

      
                                      
      
                                      
        
                                      从哪里拿数据例子读取
                                      
        
          
                                      路径参数/api/users/2req.params.id
                                      
          
                                      查询参数/api/todos?done=truereq.query.done（都是字符串）
                                      
          
                                      请求正文POST / PATCH 的 JSONreq.body（需要 express.json()）
                                      
          
                                      请求头Authorizationreq.get("authorization")
                                      
                                              
      
                                      
      
                                      
        
                                      返回写法
                                      
        
          
                                      JSON（最常用）res.json(data)
                                      
          
                                      带状态码res.status(201).json(data)
                                      
          
                                      只有状态码res.sendStatus(204)
                                      
          
                                      文本或 HTMLres.send("ok")
                                      
                                              
      
                                      
      
                                      每个请求都要有回应
                                      处理函数里忘了 res.json 或 res.send，前端就会一直转圈等到超时。提前返回时记得写 return res.status(...)，否则后面的代码还会继续执行。

                                      中间件与 REST 设计
                                      
      
                                      中间件是请求到达处理函数之前经过的一串“关卡”，可以记录日志、解析正文、检查登录。调用 next() 放行，直接 res.status(...) 就是拦下。
                                      
      
                                      
        
                                      middleware.js看日志面板的输出顺序
                                      
        

      
                                      
      
                                      REST 接口设计约定
                                      
      
                                      
        
                                      操作方法 + 路径成功常见错误
                                      
        
          
                                      列表（可筛选、分页）GET /api/todos?done=true&page=2200
                                      
          
                                      详情GET /api/todos/:id200404
                                      
          
                                      新建POST /api/todos201400 / 422 校验失败
                                      
          
                                      修改部分字段PATCH /api/todos/:id200404、403 无权限
                                      
          
                                      删除DELETE /api/todos/:id204404

                                        • 
        
                                      • 错误统一返回 { "error": "说明" }，前端处理起来简单。

                                      05
                                      数据库与 SQL
                                      
      
                                      服务器重启后内存里的数组就没了，所以数据要存进数据库。最常用的是关系型数据库（PostgreSQL、MySQL、SQLite），数据存在一张张表里，用 SQL 语言操作。下面是一个真正能执行 SQL 的练习库，已经有 users 和 todos 两张表。
                                      
      
                                      
        
                                      query.sql一次可以写多条，用分号隔开
                                      

      
                                      
      
                                      
        
                                      操作SQL对应接口
                                      
        
          
                                      建表CREATE TABLE todos (id INTEGER PRIMARY KEY, title TEXT NOT NULL, done BOOLEAN DEFAULT false)
                                      
          
                                      查SELECT * FROM todos WHERE id = 1GET
                                      
          
                                      增INSERT INTO todos (title) VALUES ('学 SQL')POST
                                      
          
                                      改UPDATE todos SET done = true WHERE id = 1PATCH
                                      
          
                                      删DELETE FROM todos WHERE id = 1DELETE
                                      
          
                                      排序、分页ORDER BY id DESC LIMIT 10 OFFSET 20列表分页
                                      
                                              
      
                                      
      
                                      别忘了 WHERE
                                      UPDATE 和 DELETE 不写 WHERE 会作用于整张表的每一行。在上面的练习库里随便试，点“还原代码”再运行就恢复了；真实数据库可没有这个按钮。
                                      
      
                                      表之间的关系
                                      todos.user_id 存的是 users.id，这叫外键：一个用户有多条待办（一对多）。用 JOIN 把它们连起来查。
                                      
    
                                      

    
    
                                      
      
                                      06
                                      在代码里用数据库
                                      
      
                                      在 Node.js 里有两种常见做法：直接写 SQL，或者用 ORM 以对象的方式操作。不管哪种，永远不要把用户输入直接拼进 SQL。
                                      
      
                                      
        
                                      代码
                                      
        
          
                                      危险：拼接字符串db.query("SELECT * FROM users WHERE email = '" + email + "'")
                                      用户输入 ' OR '1'='1 就能查出所有用户，这就是 SQL 注入
                                      
          
                                      安全：参数化查询db.query("SELECT * FROM users WHERE email = $1", [email])
                                      数据库把参数当纯数据处理，不会当成 SQL 执行
                                      
                                              
      
                                      
      
                                      用 Prisma（最流行的 Node.js ORM）

import { PrismaClient } from "@prisma/client";
const prisma = new PrismaClient();

app.get("/api/todos", async (req, res) => {
  const todos = await prisma.todo.findMany({
    where: { userId: req.user.id },
    orderBy: { id: "desc" },
  });
  res.json(todos);
});

app.post("/api/todos", async (req, res) => {
  const todo = await prisma.todo.create({

                                      07
                                      注册与登录
                                      
      
                                      登录要解决两件事：证明你是你（核对密码），以及之后的请求怎么记住你（会话或令牌）。
                                      
      
                                        
        
                                      1. 注册：前端发送邮箱和密码。后端用 bcrypt.hash(password, 10) 把密码变成不可逆的哈希再存库。数据库里绝不能存明文密码。
                                        2. 
        
                                      2. 登录：后端按邮箱查出用户，用 bcrypt.compare(输入的密码, 存的哈希) 核对。
                                        3. 
        
                                      3. 记住身份：核对通过后，生成一个会话 ID 放进 HttpOnly Cookie，或者签发一个 JWT 令牌。
                                        4. 
        
                                      4. 之后的请求：浏览器自动带 Cookie，或前端在请求头加 Authorization: Bearer 令牌。后端的鉴权中间件验证后放行（第 04 节的 requireAuth）。
                                        5. 
      
                                      
      
                                      
        
                                      Session + CookieJWT
                                      
        
          
                                      存在哪服务器存会话，浏览器只存一个 ID信息都在令牌里，服务器不用存
                                      
          
                                      退出登录删掉服务器上的会话即可令牌在过期前一直有效，要另外处理
                                      
          
                                      适合传统网站、同域的全栈应用（推荐新手）多个服务之间、移动 App
                                      
                                              
      
                                      
      
                                      看看 JWT 里有什么
                                      
      
                                      JWT 是用点分成三段的字符串。前两段只是 Base64 编码，谁都能解开，所以不能放密码等敏感信息；第三段是用服务器密钥算出的签名，篡改内容后签名就对不上了。
                                      
      
                                      
        
                                      
          
          
                                      Header 头部
                                      Payload 内容
                                      Signature 签名
                                      
          
                                      
        
                                      
      
                                      
      
                                      省事的做法
                                      自己实现登录容易出安全问题。实际项目可以用现成方案：Next.js 用 Auth.js（支持 GitHub、Google 登录），或者 Supabase Auth、Clerk 这类服务。理解上面的原理就够用了。

export async function POST(request) {

                                            11
                                            常见问题
                                            
      
                                            
        
                                            现象原因和解决
                                            
        
          
                                            'node' / 'npm' / 'code' 不是内部或外部命令（command not found）安装后没有重开终端，或者没加进 PATH。关掉所有终端和 VS Code 重新打开；还不行就重装并勾选“添加到 PATH”。
                                            
          
                                            npm install 很慢或卡住换国内镜像（第 02 节）。实在失败可以删掉 node_modules 和 package-lock.json 再装一次。
                                            
          
                                            Port 5173 is in use端口被另一个还在运行的服务器占用了。找到那个终端按 CtrlC 停掉，或者直接用 Vite 自动换的新端口。
                                            
          
                                            Cannot find module 'xxx'依赖没装：在项目根目录运行 npm install。注意终端当前目录是不是项目根目录（有 package.json 的那层）。
                                            
          
                                            保存后没有自动格式化检查是否装了 Prettier、设置里 editor.formatOnSave 是否为 true、默认格式化工具是否选了 Prettier。
                                            
          
                                            改了代码页面没变化文件是不是没保存（标签上有个圆点）？开启“自动保存”能避免这个问题。开发服务器是不是停了？
                                            
          
                                            路径里有中文或空格导致奇怪的错误项目放在纯英文、无空格的路径下，比如 ~/code/my-app。
                                            
          
                                            Windows 上 npm 报“禁止运行脚本”见第 02 节的 Set-ExecutionPolicy 命令，或者在 VS Code 终端右上角把默认终端换成 Command Prompt / Git Bash。
